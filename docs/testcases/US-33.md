# Test case nghiệm thu US-33: Khuyến mãi theo kênh (API T-33.1, màn admin T-33.2)

> Cập nhật: 2026-11-20 · Task T-33.1, T-33.2 · Người viết: LucVT
> Code liên quan: `web/src/features/promotion-admin/*`, `web/src/features/product-admin/PriceHistoryDialog.tsx`; backend `promotion/*` (V23)
> Hợp đồng: [api-contracts.md](../specs/api-contracts.md) mục "Khuyến mãi"; quyết định: [decisions.md](../specs/decisions.md) #53
> **AC US-33:** nhập voucher Shopee 12.12 → gọi API khuyến mãi của kênh SHOPEE thì trả đúng voucher đó, hết hạn thì không trả; lịch sử giá lưu mỗi lần đổi.
> **Tiêu chí T-33.2:** nhập / sửa / xoá

## Chuẩn bị
Backend + web local (`run-web.bat`, backend profile `default`: kiểm log Flyway ghi `localhost:5432`). Đăng nhập `/admin/promotions` bằng tài khoản admin (dùng chung phiên với `/admin/products`).
API công khai để đối chiếu: `GET http://localhost:8080/api/promotions?channel=SHOPEE&upcomingDays=7`.

## A. Voucher (AC)
| TC | Bước | Mong đợi |
|---|---|---|
| TC-33-01 | "+ Thêm khuyến mãi" → Voucher, kênh Shopee, tên "Voucher 12.12", Bắt đầu hôm nay, Kết thúc 12/12 23:59, mã `sale1212`, giảm 30000, đơn tối thiểu 300000 → Lưu | Dòng mới: Shopee, mã `SALE1212` (tự viết hoa), "−30.000đ / đơn từ 300.000đ", giờ đúng như đã nhập, nhãn **Đang chạy** |
| TC-33-02 | Gọi API công khai `channel=SHOPEE`, rồi `channel=TIKTOK` | SHOPEE có `SALE1212`, `startsAt`/`endsAt` dạng `+07:00` khớp giờ đã nhập; TIKTOK **không** có |
| TC-33-03 | DB local: `UPDATE promotion SET starts_at = now() - interval '2 day', ends_at = now() - interval '1 minute' WHERE voucher_code = 'SALE1212'`; tải lại màn và gọi lại API | API công khai không còn trả voucher (cả khi `upcomingDays=30`); màn admin vẫn có dòng, nhãn **Hết hạn**, dòng mờ; lọc "Hết hạn" thấy, lọc "Đang chạy" không thấy |
| TC-33-04 | Thêm voucher khác cùng kênh Shopee, mã `SALE1212` | Không lưu; ô Mã voucher đỏ "Kênh SHOPEE đã có voucher SALE1212". Cùng mã ở TikTok thì lưu được |
