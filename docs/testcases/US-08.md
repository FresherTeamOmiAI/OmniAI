# Test case nghiệm thu US-08: Quản lý sản phẩm (admin)

> Cập nhật: 2026-11-09 · Task T-08.1, T-08.2 · Người viết: LucVT
> Code liên quan: `backend/.../catalog/*`, `backend/.../common/SecurityConfig.java`, migration `V5__import_catalog_80.sql`
> Hợp đồng API: [api-contracts.md](../specs/api-contracts.md), mục "Admin sản phẩm"
> **AC:** Given đăng nhập admin · When thêm/sửa/ẩn sản phẩm · Then `GET /api/products` phản ánh ngay; sản phẩm ẩn không hiện ở store và `GET /api/products/{id}` trả 404.

Phần API của US-08 (T-08.1, T-08.2) đạt khi mọi TC tự động PASS và collection Postman chạy hết không có request nào FAIL. Màn admin (T-08.3) sẽ thêm TC thủ công trên trình duyệt sau.

Có 3 cách test, dùng cho 3 mục đích khác nhau:

| Cách | Dùng khi | Cần chạy gì | Đụng DB dev? |
|---|---|---|---|
| A. JUnit (`mvn test`) | Trước khi push/mở PR, CI | Chỉ Docker Desktop | **Không**. Test dùng container Postgres riêng, mỗi test rollback |
| B. Postman | Reviewer/PO kiểm tra API, demo | Docker + backend | Có. Tạo 1 sản phẩm test rồi tự ẩn ở cuối |
| C. REST Client (`.http`) | Dev thử nhanh 1 request trong VS Code | Docker + backend | Có, như B |

## A. Test tự động (JUnit + Testcontainers)

### Chuẩn bị (làm 1 lần)
1. **Docker Desktop đang chạy.** Kiểm tra: `docker info`. Không cần bật `infra-up.bat`, test tự bật container Postgres riêng rồi tự xóa.
2. **Java 21 và Maven** (repo chưa có `mvnw`). Kiểm tra: `java -version`, `mvn -v`.
3. Lần chạy đầu Testcontainers kéo image `pgvector/pgvector:pg16` (~600 MB sau giải nén), nên mất vài phút. Nếu đã chạy `infra-up.bat` thì image có sẵn. Các lần sau ~1 phút.

Không cần chạy backend, AI Brain hay web. Test tự chạy app trong JVM, AI Brain được mock.

### Lệnh chạy
Mở terminal ở thư mục `backend/`:

| Mục đích | Lệnh |
|---|---|
| Toàn bộ test backend | `mvn test` |
| Chỉ test API admin | `mvn test -Dtest=AdminProductApiTest` |
| Chỉ test migration/catalog | `mvn test -Dtest=OmniAiApplicationTests` |
| Một ca cụ thể | `mvn test -Dtest=AdminProductApiTest#duplicateSkuIsConflict` |
| Mọi phần của repo (backend, ai-brain, bench, web) | `tools\systembat\test-all.bat` ở thư mục gốc |

Trong IntelliJ/VS Code: mở `AdminProductApiTest.java`, bấm nút ▶ cạnh tên class hoặc tên hàm.

### Đọc kết quả

## B. Test thủ công bằng Postman

File collection: `backend/http/OmniAI-admin-products.postman_collection.json`. Gồm 25 request chia 8 nhóm, mỗi request có script tự kiểm tra, nên chỉ cần nhìn PASS/FAIL.

### Chuẩn bị
1. Cài Postman (desktop app; bản web không gọi được `localhost` nếu chưa cài Postman Agent).
2. Bật Docker Desktop, rồi chạy ở thư mục gốc repo:
   - `tools\systembat\infra-up.bat` (Postgres, Redis, RabbitMQ)
   - `tools\systembat\run-backend.bat` (cổng 8080). Chờ log có `Started OmniAiApplication`.
   - Mở http://localhost:8080/actuator/health, thấy `{"status":"UP"}` là được.
3. Tài khoản admin: mặc định `admin` / `admin`. Nếu `.env` có `ADMIN_USERNAME`/`ADMIN_PASSWORD` khác thì sửa biến collection ở bước dưới.

### Import collection
1. Postman → **Import** (góc trên trái) → kéo thả file `OmniAI-admin-products.postman_collection.json` → **Import**.
2. Bấm vào collection **OmniAI - Admin sản phẩm (T-08.1)** → tab **Variables**, kiểm tra:

| Biến | Mặc định | Ý nghĩa |
|---|---|---|
| `base_url` | `http://localhost:8080` | Địa chỉ backend |
| `admin_user`, `admin_pass` | `admin`, `admin` | Tài khoản admin, đổi nếu `.env` khác |
| `test_sku`, `test_sku_lower`, `product_id` | (trống) | Request "Tạo mới" tự điền, **không cần sửa** |

3. Tab **Authorization** của collection đã đặt sẵn **Basic Auth** dùng 2 biến trên. Request nào không cần đăng nhập (store, health, ca 401) đã tự đặt **No Auth**.

### Cách 1: chạy cả bộ bằng Collection Runner (khuyên dùng)
1. Chuột phải vào collection → **Run collection**.
2. Giữ nguyên thứ tự request (không bật "Run in random order"), Iterations = 1 → **Run OmniAI - Admin sản phẩm**.
3. Đạt khi tab **Failed** = 0. Chạy mất khoảng 10 giây.

### Cách 2: chạy từng request
Mở từng request theo thứ tự thư mục 0 → 9, bấm **Send**, rồi xem tab **Test Results** ở khung response. Phải chạy **"3. Tạo mới → Tạo mới -> 201"** trước các request nhóm 5, 6, 9, vì chúng dùng `{{product_id}}` do request này lưu lại.

### Cách 3: chạy bằng dòng lệnh (newman)
```bash
npm install -g newman        # 1 lần
newman run backend/http/OmniAI-admin-products.postman_collection.json
# đổi mật khẩu: thêm --env-var admin_pass=<mật khẩu>
```
Đạt khi bảng cuối có cột `failed` toàn 0.

### Lưu ý
- **Dữ liệu test nằm lại trong DB dev.** Không có xóa cứng (G-07), nên mỗi lần chạy để lại 1 sản phẩm ẩn có SKU `QAxx-SER-NN`. Store và AI không thấy chúng. Muốn DB sạch hẳn: `tools\systembat\infra-down.bat --reset` (**xóa toàn bộ dữ liệu DB local**), rồi `infra-up.bat` và chạy lại backend. Flyway sẽ nạp lại 80 SKU.
- Request "Tạo mới" báo `409` thì SKU ngẫu nhiên trùng với lần chạy trước. Bấm Send lại hoặc chạy lại Runner.
- Gửi tiếng Việt bằng `curl` trong Git Bash/PowerShell có thể hỏng dấu (thấy `400` thiếu lỗi `name`). Postman và REST Client không bị.

### Lỗi thường gặp
| Hiện tượng | Nguyên nhân | Cách xử lý |
|---|---|---|
| `Error: connect ECONNREFUSED 127.0.0.1:8080` | Backend chưa chạy | Chạy `run-backend.bat`, chờ health `UP` |
| Mọi request admin đều `401` | Mật khẩu khác `.env` | Sửa `admin_pass` trong Variables, bấm **Save** |
| Nhóm 5, 6 báo `404` hoặc URL có `{{product_id}}` | Chưa chạy "Tạo mới" hoặc nó lỗi | Chạy lại request "Tạo mới" cho tới khi `201` |
| Backend log `Port 8080 was already in use` | Đã có backend khác đang chạy | Dùng luôn backend đó, hoặc `stop-all.bat` rồi chạy lại |
| `500` ở bất kỳ request nào | Lỗi chưa xử lý | Chụp log backend, báo LucVT |
